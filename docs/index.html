Ecosystems: Cargo 🦀 npm 🟢 PyPI 🐍 Go 🐹 Composer 🐘

What ships

Dependency intelligence, end to end

One binary discovers every manifest, resolves the registries, classifies each jump, and writes a report you can hand to a teammate or a CI job.

Parallel Multi-Ecosystem Scanning

Walks a repository tree while honouring .gitignore, parses Cargo, npm, PyPI, Go and Composer manifests, and queries all five registries concurrently through Tokio.

Coverage5 ecosystems

SemVer Risk Classification

Compares each bump against the declared requirement and labels it ● Safe, ● At-Risk, ● Breaking, up-to-date, or unknown — with pre-releases filtered out.

RulesSemVer 2.0 + declared range

Per-Library AI Briefings

Every outdated package gets its own Markdown analysis: breaking changes, security and CVE context, performance impact, and actionable migration advice — not a generic changelog dump.

Output4-section briefing

Free Local AI, or Bring Your Key

Run summaries entirely on your machine with Ollama, or plug in Gemini, OpenAI, OpenRouter, or any OpenAI-compatible proxy. Keys stay in your config; no telemetry, no shared key, no RustyDeps proxy.

PrivacyLocal-first BYOK

Disk Cache & Circuit Breaker

Analyses are cached per ecosystem, package and target version, so repeat scans cost zero tokens. Invalidate with --no-cache or wipe with rustydeps cache clear; auth, quota and model errors stop after the first failure.

Repeat AI0 tokens

Self-Contained HTML Report

One file with inline CSS and JS: project cards, risk dots, search and risk filters, expandable dependency drawers, copy-ready upgrade commands, and a per-project “Update All”. No CDN, no server.

Dependencieszero at runtime

AI that stays yours

Per-library briefings. Free by default.

Ollama runs the model on your hardware, so local summaries need no account, no key, and no network. Prefer a hosted model? Point RustyDeps at your own provider key — the binary calls it directly and caches the result on disk.

  • ✔Only outdated, registry-resolved packages are analysed — up-to-date drawers show a plain status card.
  • ✔At most four concurrent requests with a 45-second timeout; a failure degrades to the standard changelog link.
  • ✔A one-second Ollama preflight warns once if the daemon is offline; cached briefings are still applied.
  • ✔The report names the model behind a cached briefing, for example ⚡ Cached (llama3.2:3b).

Quickstart

From clone to report in three steps

A single Rust binary, or a prebuilt multi-arch Docker image. No language runtime required either way.

Step 1 · Install v0.3.1
cargo install --git https://github.com/AlexDevsTheWeb/rustydeps --tag v0.3.1

Installs the tagged release, including the AI summarizer and cache commands.

docker run --rm -v /path/to/repo:/workspace ghcr.io/alexdevstheweb/rustydeps:0.3.1

Multi-arch Linux image (amd64 + arm64). The report lands in the mounted directory; add --no-open for CI.

Step 2 · Scan
rustydeps scan .
-o report.html --no-open
Choose the path, skip the browser
--format json
Machine-readable, banner suppressed
--offline
No registry calls; alias --no-fetch
Step 3 · Add AI (optional)
rustydeps scan . --ai --ai-provider ollama
BYOK config: ~/.config/rustydeps/config.json Free + offline with Ollama --no-ai always wins
CI recipe: use the Docker image with scan /workspace --no-open and archive rustydeps-report.html as a build artifact.
