# v0.4.0 — README and landing page sync

## Motivation

v0.4.0 shipped release-note grounding, custom-provider coverage, and the
multi-package regression work, but `README.md` and `docs/index.html` still
advertised v0.3.1. The brief is
`doc/raw/2026-11-27/2026-11-27-v0.4.0.md`.

## README changes

- Banner, shields.io badge, Cargo install tag, Docker examples, Docker tag note,
  release example, and release commands now use v0.4.0 / `0.4.0`.
- Added an explicit `docker pull ghcr.io/alexdevstheweb/rustydeps:0.4.0`.
- The AI feature bullet names all five repository sources (crates.io, npm, PyPI,
  Packagist, Go metadata).
- The grounding section now states `CACHE_FORMAT_VERSION = 2`, the one-time
  regeneration of v0.3.x entries, and `rustydeps cache clear`.
- `--offline` is documented precisely: it skips registry version lookups and
  official release-note fetching, never contacts a registry or GitHub, and still
  applies cached briefings. An enabled AI provider is still called on cache
  misses, so `--no-ai` is the fully hermetic option.

## Landing page changes

- Title, meta description, header badge, hero release pill, report mock header,
  and footer now say v0.4.0.
- Hero and quickstart install commands use `--tag v0.4.0`; Docker commands use
  the `0.4.0` GHCR tag.
- The AI feature card is now **Grounded Per-Library AI Briefings**, naming the
  registry metadata sources and official GitHub notes.
- The AI section adds release-note grounding and `GITHUB_TOKEN`/`GH_TOKEN`
  bullets; the cache card mentions `CACHE_FORMAT_VERSION = 2`.
- All release links point at `releases/tag/v0.4.0`; all 15 `data-copy`
  controls remain, with the four version-bearing commands on v0.4.0.

## GHCR tag correction

The brief asked for `ghcr.io/alexdevstheweb/rustydeps:v0.4.0`. The Docker
workflow uses `docker/metadata-action` with `type=semver,pattern={{version}}`,
which publishes `0.4.0` and `0.4` — no `v`. The live GHCR tag list confirms
`["0.4.0", "0.4"]`, so the docs use `0.4.0`. Release URLs keep the git tag
`v0.4.0`.

## Verification

- `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`,
  `cargo test --all-targets` — clean; 162 unit + 5 integration tests.
- `html.parser` stack check — 0 errors; 155 opening and closing `<div>` tags.
- Headless Chromium at 1365 px and 390 px — `scrollWidth == innerWidth`, no
  horizontal overflow; title, badges, grounding card, and token text present.
- 15 `data-copy` attributes preserved; no stale `0.3.1`/`v0.3.1` text remains
  outside the intentional `v0.3.x` cache-compatibility notes.
- Release URL `releases/tag/v0.4.0` returns HTTP 200; GHCR exposes `0.4.0` and
  `0.4`.

## Known limitation

`--offline` does not disable an already-enabled AI provider for cache misses;
the docs now say so explicitly and point to `--no-ai`. Making `--offline`
cache-only is a possible follow-up, but it would change existing behaviour.
