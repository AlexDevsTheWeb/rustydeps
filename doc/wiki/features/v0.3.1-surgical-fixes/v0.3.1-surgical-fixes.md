# v0.3.1 — surgical AI fixes

## Motivation

The 0.3.0 AI path cached every analysis but offered no way to inspect or reset
that state from the CLI. An Ollama daemon that was not running produced one
transport warning per package, and the report's cache badge did not say which
model produced an analysis. The brief is
`doc/raw/2026-10-21/2026-10-21-0.3.1.md`.

## Cache management

`rustydeps cache clear` walks `~/.cache/rustydeps/changelogs/`, removes every
file, and prints `✔ Cleared X cached AI changelog entries.` A missing directory
is not an error and reports zero. The work lives in `SummaryCache::clear`
(`src/ai/cache.rs`), which returns `io::Result<usize>` and is unit-tested against
a temporary root.

`rustydeps scan --no-cache` sets `AiOverrides::no_cache`, which resolves
`AiSettings::force_refresh` to `true` for that run. The summarizer skips cache
reads, forces fresh analyses, and still writes each result back to the cache
when caching is enabled. This refreshes entries without deleting them first.

## Ollama preflight

Before spawning package tasks, a summarizer configured for Ollama probes the
daemon once:

```text
GET <ollama-origin>/api/tags      timeout: 1000 ms
```

The endpoint path is rebuilt from the configured base, so both
`http://localhost:11434/v1` and a full chat-completions URL resolve to
`http://localhost:11434/api/tags`. On failure the run logs one warning:

```text
WARN Ollama daemon is offline at http://localhost:11434. Tip: Run 'ollama serve' or 'brew services start ollama'.
```

The scan-local circuit breaker is tripped, so no package-level chat request is
attempted. Cache hits still apply: the tasks run, but `analyze` returns after the
cache lookup. A daemon that is online proceeds normally.

## Model-aware cache badge

`ClassifiedDependency` now carries `ai_model: Option<String>`. A cache hit
copies `CachedSummary::model`; a fresh analysis records the configured model.
The report row exposes `ai_model` (falling back to `unknown`) and the template
renders:

```html
⚡ Cached (llama3.2:3b)
```

instead of the model-agnostic `⚡ Cached analysis`.

## Integration tests

The crate now exposes a library target (`src/lib.rs`) so integration tests can
use the public API without spawning the binary. `tests/ai_integration_tests.rs`
uses `wiremock = "0.6"` for four end-to-end cases:

| Test | Asserts |
|------|---------|
| `parses_a_successful_chat_completion` | 200 response text, model and message roles in the request |
| `a_rate_limit_response_trips_the_circuit_breaker` | 429 stops the scan after the in-flight batch |
| `a_not_found_response_is_fatal` | 404 is classified fatal and names the URL/status |
| `an_offline_ollama_daemon_skips_every_chat_request` | failed `/api/tags` probe issues zero chat requests |

## Verification

`cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`,
`cargo test`, and `cargo build --release` all pass. `cargo run -- cache clear`
was verified against an isolated `XDG_CACHE_HOME` so the real cache was not
destroyed: two seeded entries were removed and the directory was empty.

See [[free-local-ai]] for the provider behavior this builds on.
