---

## 🎯 Context & Core Value Proposition

`rustydeps` evaluates dependency updates across multiple registries (Cargo, npm, PyPI, Go, Composer).
The **core value proposition and primary differentiator ("killer feature")** of RustyDeps in Milestone 0.3.0 is **Granular, Per-Library AI Analysis**.

Instead of generating a generic, high-level summary for an entire repository or project folder, RustyDeps performs a **deep, tailored AI evaluation for each individual outdated package** (e.g., upgrading `tokio` from `1.20` to `2.0`, or `express` from `4.18` to `5.0`). Every single library drawer in the HTML report gets its own custom-tailored analysis.

To protect user privacy and avoid centralized infrastructure costs, this feature uses a **BYOK (Bring Your Own Key)** model with a local JSON configuration file (`~/.config/rustydeps/config.json`) and local result caching (`~/.cache/rustydeps/changelogs/`).

## 📋 Implementation Checklist

### 1. Branch & Version Setup
* Create and checkout feature branch `feat/ai-changelog-summarizer` off `development`.
* Ensure project version in `Cargo.toml` is set to `0.3.0-dev` (or target `0.3.0`).

### 2. Configuration Management (`src/config/mod.rs` & `~/.config/rustydeps/config.json`)
* Implement a structured configuration loader:
  - File location: `~/.config/rustydeps/config.json` (fallback to project-local `.rustydeps.json` if present).
  - Config Schema:
    ```json
    {
      "ai": {
        "enabled": true,
        "provider": "openai",
        "api_key": "sk-...",
        "model": "gpt-4o-mini",
        "endpoint": "https://api.openai.com/v1",
        "max_tokens": 400,
        "cache_enabled": true
      }
    }
    ```
  - Environment Variable Overrides:
    - `RUSTYDEPS_AI_ENABLED` (bool)
    - `RUSTYDEPS_AI_PROVIDER` (`openai`, `gemini`, `ollama`)
    - `RUSTYDEPS_AI_API_KEY` (string)
    - `RUSTYDEPS_AI_MODEL` (string)
    - `RUSTYDEPS_AI_ENDPOINT` (string URL)
  - CLI Flag Overrides:
    - `--no-ai` to temporarily disable AI summarization during scan.
    - `--ai-model <MODEL>` to override model.

### 3. Per-Library AI Prompt Engineering & Analysis (`src/ai/client.rs` & `src/ai/mod.rs`)
* Build an async, OpenAI-compatible REST client using `reqwest` (supporting OpenAI, Gemini, Ollama at `http://localhost:11434/v1`).
* **Granular Per-Package Prompt Architecture:**
  - Invoked strictly per library upgrade tuple: `(ecosystem, package_name, current_version, target_version)`.
  - The System Prompt MUST instruct the LLM to deliver a package-specific breakdown formatted in Markdown:
    - 🚨 **Breaking Changes & Deprecations:** Specific API removals, signature changes, or renamed methods for this library.
    - 🛡️ **Security & Vulnerability Context:** Highlighting fixed CVEs or security advisories resolved in this version jump.
    - ⚡ **Performance & Architectural Impact:** MSRV (Minimum Supported Language/Rust Version), runtime changes, or new async primitives.
    - 💡 **Actionable Migration Advice:** Concrete, code-level migration instructions or replacement snippet (e.g. "Replace `tokio::spawn_blocking` with...").

### 4. Local Per-Library Caching Engine (`src/ai/cache.rs`)
* Store generated summaries on disk at `~/.cache/rustydeps/changelogs/{ecosystem}_{package}_{target_version}.json`.
* Key format: `{ecosystem}_{package}_{target_version}` (e.g. `cargo_tokio_2.0.0.json`).
* Before making an HTTP request to the LLM, check if a cached summary exists for that exact package version.
* If cached, load from disk instantly (0 latency, $0 cost across multiple projects sharing the same dependency version).

### 5. Graceful Fallback & Error Handling
* The scanning engine MUST NEVER fail or crash due to AI errors.
* If AI is disabled, key is missing, rate-limited, offline, or request times out (e.g. 10s timeout per library):
  - Log a subtle info/warning message in CLI.
  - Set AI summary field to `None` in the package data model.
  - The HTML report renders the standard changelog link without error.

### 6. HTML Report Integration (`templates/report.html`)
* Update the Askama HTML template so each library's drawer features a dedicated, rich **🤖 AI Library Release Analysis** card:
  - Displayed inside the expanded drawer of the specific library.
  - Formatted Markdown rendering (collapsible sections, code blocks, hazard badges).
  - Cache indicator badge: "⚡ Cached analysis".
