### Step 2 — SemVer Classifier Subsystem (`src/classifier/`)
1. **Add `semver` crate** to `Cargo.toml`.
2. **Define `UpdateType` Enum in `src/model.rs`**:
   - `Safe`: Patch bumps (`1.0.0` -> `1.0.1`) and minor bumps (`1.0.0` -> `1.1.0`).
   - `AtRisk`: Minor bumps with deprecation notes or constraint mismatches.
   - `Breaking`: Major version bumps (`1.35.1` -> `2.0.0`) or breaking constraint changes.
   - `UpToDate`: Current version matches latest version.
   - `Unknown`: Unparseable versions or missing registry data.
3. **Prerelease Filtering & Latest Stable Logic**:
   - When evaluating registry versions, filter out prereleases (`alpha`, `beta`, `rc`) unless the current installed version is explicitly a prerelease. Ensure target version defaults to the latest stable release.
4. **Classifier Engine (`src/classifier/mod.rs`)**:
   - Implement `classify_update(current: &str, latest: &str) -> ClassifiedDependency`.
   - `ClassifiedDependency` DTO:
     - `name: String`
     - `ecosystem: Ecosystem`
     - `current_version: String`
     - `latest_version: String`
     - `update_type: UpdateType`
     - `manifest_path: PathBuf`
     - `is_dev_dependency: bool`
     - `ai_summary: Option<String>`

### Step 3 — AI Summary Module (`src/ai/`)
1. Create `src/ai/mod.rs` and `src/ai/summary.rs`:
   - Activated when `--ai` flag is present.
   - For `Breaking` and `AtRisk` dependencies, generate a concise 1-line AI summary explaining the key changes or migration risk.
   - Support environment variables for LLM provider API (e.g. `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` / local endpoint) or graceful fallback when no API key is provided.
   - If `--ai` is absent or API call fails/unconfigured, populate `ai_summary` with a standard fallback description (e.g. *"Major version bump — potential breaking API changes"*).
