# TASK: Integrate Exported Stitch HTML Template into Rust Report Engine

## Context
Phase 4 (HTML Report Engine) requires generating an interactive, standalone HTML report.
An exact HTML/CSS template generated by Google Stitch is provided as `src/templates/report_stitch.html`.

---

## Instructions

### Step 1 — Locate / Ingest the Template
- Load the HTML template from `src/templates/report_stitch.html`.
- If using `askama`, place or symlink the template in `templates/report.html`.

### Step 2 — Wire Up Dynamic Data Placeholders
Refactor the HTML template to replace static mockup rows with dynamic loops over the scanned Rust data model (`ClassifiedDependency` grouped by project/manifest):

1. **Project Grouping Cards/Accordions:**
   - Loop over discovered projects (`backend-api`, `web-dashboard`, etc.).
   - Display manifest ecosystem badge (`CARGO`, `NPM`, etc.) and total risk counts.
2. **Dependency Rows:**
   - Render package name, ecosystem, `current_version -> latest_version`.
   - Apply risk indicator dots:
     - `● major` (red) for `Breaking`
     - `● minor` (amber/yellow) for `AtRisk`
     - `● patch` (green) for `Safe`
3. **AI Summaries & Inline Drawers:**
   - Render the `AI` badge and summary line.
   - Inject the inline expandable drawer containing the extended changelog and copyable CLI update command (e.g. `cargo update -p <crate> --precise <ver>`).
4. **Interactive Features:**
   - Keep the JavaScript search/filter logic for the search bar and filter pills.
   - Ensure the `#empty-state` container and project-level `Update All` popover are hooked up correctly.

### Step 3 — Verification
1. Ensure the final generated report is a **100% self-contained HTML file**.
2. Run `cargo test`, `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`.
3. Test with: `cargo run -- scan . -o report.html` and open `report.html` to confirm visual fidelity matches Stitch UI v4.
