# TASK: Phase 4 — Interactive HTML Report Engine (Askama/Tera & Self-Contained HTML)

## Context
Phase 3 is complete and shipped as Draft PR on branch `feat/phase-3`.
We now have:
- `ClassifiedDependency` with `UpdateType` (`Safe`, `AtRisk`, `Breaking`, `UpToDate`, `Unknown`).
- Templated AI summaries per dependency.
- CLI scanner with ASCII banner and `--offline` support.
- Fully validated OKF LLM-Wiki specifications, including `doc/wiki/html-report-spec.md`.

We are now moving to **Phase 4**, which focuses on building the **Interactive HTML Report Engine**.

---

## Instructions

### Step 1 — HTML Templating Engine Integration
1. Integrate an HTML templating engine in `Cargo.toml` (e.g. `askama`, `tera`, or `maud`).
2. Implement the report generator in `src/report/mod.rs` (or `src/report/html.rs`).
3. The report must consume the scanned and classified dependencies (`Vec<ClassifiedDependency>`) and render a single **self-contained HTML file** (embedded CSS, embedded minimal JS for interactivity, zero external CDN dependencies so it opens offline seamlessly in any browser).

---

### Step 2 — Implement the Approved Stitch UI v4 Layout
Follow `doc/wiki/html-report-spec.md` and the Stitch UI v4 design strictly:

1. **Project-Centric Grouping:**
   - Group dependencies by project/manifest (`backend-api`, `web-dashboard`, `ml-worker`, etc.).
   - Card/accordion header showing project name, ecosystem tag (`CARGO`, `NPM`, etc.), manifest path, and project-level risk breakdown pill.

2. **Industrial Dark Mode Styling:**
   - Palette: Zinc dark background (`#09090b`), card surfaces (`#18181b`), subtle 1px borders (`#27272a`).
   - Clean, high-contrast monospace typography for package names, constraints, and version jumps (`1.35.1 → 2.0.0`).

3. **Minimalist Solid Risk Indicators:**
   - `● major` (red dot) for `Breaking`
   - `● minor` (amber/yellow dot) for `AtRisk`
   - `● patch` (emerald green dot) for `Safe`
   - No heavy/glossy translucent badges.

4. **Discrete AI Summary:**
   - Small, subtle `AI` neutral gray tag + 1-line summary text for each package.

5. **Inline Expandable Drawer (`.dependency-drawer`):**
   - Clicking a row or chevron expands a detail box showing the extended AI changelog summary card and a code block with a one-click copy button containing the exact CLI update command (e.g., `cargo update -p tokio --precise 2.0.0`).

6. **Search & Filter Bar + Empty State:**
   - Filter input (`Filter packages... /`) and quick filter pills (`All`, `● Breaking`, `● At-Risk`, `● Safe`).
   - An empty state block (`#empty-state`, hidden by default) that displays when search/filter returns 0 matches (*"No dependencies match your filter"*).

7. **Project "Update All" Action:**
   - "Update All" button in each project header that displays/copies all combined update commands for that manifest.

---

### Step 3 — CLI Output & Browser Auto-Open
1. Update `rustydeps scan`:
   - When `--output` / `-o` is specified (e.g., `-o report.html` or `--format html`), write the generated self-contained HTML report to the target file.
   - Default output file when `--format html` is specified without `-o`: `rustydeps-report.html`.
   - Print a clear CLI confirmation message with the generated file path and option to open in browser.
