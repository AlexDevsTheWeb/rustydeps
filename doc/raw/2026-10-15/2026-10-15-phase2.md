# TASK: Phase 2 — Manifest Parsers (Cargo & npm) & Registry HTTP Clients

## Context
Phase 1 is complete and shipped as Draft PR #2. The Rust crate, CLI arguments (`clap`), and file system scanner (`ignore::WalkBuilder`) are in place and tested.

We are now moving to **Phase 2**, which focuses on:
1. Defining the core `PackageParser` trait and parsing `Cargo.toml` and `package.json`.
2. Implementing HTTP registry clients with `reqwest` and `tokio` to fetch package metadata concurrently from crates.io and npmjs.org.

---

## Instructions

### Step 1 — Define the `PackageParser` Trait & Parser Engine (`src/parser/`)
Create a modular parser subsystem in `src/parser/`:
1. **`src/parser/mod.rs`**:
   - Define the `PackageParser` trait with methods:
     - `fn can_parse(&self, manifest: &DiscoveredManifest) -> bool`
     - `fn parse(&self, manifest: &DiscoveredManifest) -> Result<Vec<ParsedDependency>>`
   - Define DTO `ParsedDependency`:
     - `name: String`
     - `current_version: String` (SemVer constraint or exact version)
     - `ecosystem: Ecosystem` (`Cargo`, `Npm`, etc.)
     - `manifest_path: PathBuf`
     - `is_dev_dependency: bool`
2. **`src/parser/cargo.rs` (`CargoParser`)**:
   - Parse `Cargo.toml` files using `cargo_toml` crate or `toml` serde parser.
   - Extract `[dependencies]`, `[dev-dependencies]`, and workspace dependencies where present.
3. **`src/parser/npm.rs` (`NpmParser`)**:
   - Parse `package.json` files using `serde_json`.
   - Extract `dependencies` and `devDependencies`.

---

### Step 2 — HTTP Registry Clients (`src/registry/`)
Create an asynchronous, concurrent registry client module in `src/registry/`:
1. **`src/registry/mod.rs`**:
   - Trait or struct `RegistryClient` for querying package registries.
   - Method `async fn fetch_latest_version(&self, name: &str) -> Result<String>`.
2. **`src/registry/crates_io.rs` (`CratesIoClient`)**:
   - Endpoint: crates.io API (`/api/v1/crates/{crate_name}`)
   - Header requirement: Custom `User-Agent` (e.g. `RustyDeps/0.1.0` as required by crates.io terms).
   - Extract `crate.max_version` or latest non-prerelease version from `versions`.
3. **`src/registry/npm.rs` (`NpmRegistryClient`)**:
   - Endpoint: npm registry (`registry.npmjs.org/{package_name}`)
   - Extract `dist-tags.latest`.
4. **Concurrency & Rate Limiting**:
   - Use `tokio` tasks (`futures::future::join_all` or `tokio::spawn`) to query registries in parallel with a concurrency limit (e.g., max 10 concurrent requests using `tokio::sync::Semaphore`).

### Step 3 — CLI Integration & Wire-Up
Update `src/main.rs` / `src/scanner.rs`:
- When `rustydeps scan` is executed:
  1. Scan for manifest files.

  3. Query registries asynchronously for latest versions.
  4. Output a clean summary to stdout/logging showing found packages, current versions, and latest registry versions.
