# Task Prompt — Phase 5: Expanded Ecosystem Parsers & Registry Clients (PyPI, Go, Composer)

## Context & Objective
RustyDeps currently supports scanning and resolving dependencies for Cargo (`Cargo.toml`) and npm (`package.json`).
In this phase, you will extend the `PackageParser` trait and `RegistryClient` infrastructure to support three additional major ecosystems:
1. **Python (PyPI)**: Parse `pyproject.toml` (PEP 621 / Poetry) and `requirements.txt`.
2. **Go**: Parse `go.mod`.
3. **PHP (Composer)**: Parse `composer.json`.

Because our architecture relies on generic traits (`PackageParser`, `RegistryClient`) and the report engine (Stitch UI v4) already contains UI cards for `PYPI`, `GO`, and `COMPOSER`, adding these ecosystems requires zero changes to the HTML template layout — they will seamlessly render as live data cards!

---

## Technical Specifications

### 1. Python Parser & Registry (`PyPI`)
- **Parser (`src/parser/pypi.rs`)**:
  - Implement `PackageParser` for `pyproject.toml` (standard `[project.dependencies]`, Poetry `[tool.poetry.dependencies]`) and `requirements.txt`.
  - Handle standard specifiers (e.g. `requests >= 2.28.0`, `flask == 3.0.0`, `pydantic ~ 2.5`).
- **Registry Client (`src/registry/pypi.rs`)**:
  - Query PyPI JSON API.
  - Parse version or filter releases for the latest stable release.

### 2. Go Parser & Registry (`Go`)
- **Parser (`src/parser/go.rs`)**:
  - Implement `PackageParser` for `go.mod`.
  - Extract module path and direct `require` statements.
- **Registry Client (`src/registry/go.rs`)**:
  - Query Go registry API.
  - Extract the highest stable SemVer version.

### 3. PHP Composer Parser & Registry (`Composer`)
- **Parser (`src/parser/composer.rs`)**:
  - Implement `PackageParser` for `composer.json` (`require` and `require-dev` objects).
  - Skip PHP engine pseudo-packages (e.g. `php`, `ext-json`, `ext-mbstring`).
- **Registry Client (`src/registry/composer.rs`)**:
  - Query Packagist API.
  - Extract the latest stable version tag.

### 4. Integration & Wire-Up
- Register all new parsers in `default_parsers()` in `src/parser/mod.rs`.
- Update `src/model.rs` `Ecosystem` enum to include `Pypi`, `Go`, `Composer` with proper ecosystem badges and lowercase labels (`pypi`, `go`, `composer`).
- Wire into the async fetch pipeline in `src/main.rs`.
- Ensure report data mapping (`src/report/mod.rs`) assigns the correct ecosystem badge CSS classes so the Stitch template renders them in their respective project cards.

3. Add unit tests for each new parser and registry client (mock HTTP/json parsing). All tests must pass (`cargo test`).
4. Perform a live smoke test against sample manifest files for Python, Go, and Composer.
5. Update Wiki under `doc/wiki/` (features & architecture) and validate OKF compliance (`python3 validate_okf.py`).
