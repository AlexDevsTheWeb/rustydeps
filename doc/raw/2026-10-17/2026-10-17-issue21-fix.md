# Opencode Prompt: Fix CLI Progress Bar Rendering & Refine Report HTML UX

## Context & Objectives
We reviewed actual execution screenshots of `rustydeps` CLI and the generated HTML report.
Two areas need refinement before finalizing the `v0.2.0` release:
1. **CLI Progress Bar Cleanliness:** Fix `indicatif` progress bar line duplications and ensure the progress counter smoothly updates in-place to `N/N`.
2. **HTML Report Usability & Layout Refinements:** Improve project card disclosure UX, hide clutter when collapsed, and group/sort dependencies by risk severity.

---

## Part A: Fix CLI Progress Bar Artifacts (`indicatif`)

### Identified Issues
- Standard `println!` / `eprintln!` calls during scanning push the `indicatif` progress bar down, leaving duplicate progress bar lines (`Scanning repositories [━━━━━ ] X/31`) in terminal scrollback history.
- Asynchronous tasks cause the progress bar count to stall at intermediate counts (e.g., 14/31) while subsequent outputs bypass the progress bar.

### Required Code Fixes (`src/cli/` or `src/scanner/`)
1. **In-place Progress Updates:**
   - Use `indicatif::MultiProgress` or a single managed `ProgressBar` with `ProgressStyle::default_bar()`.
   - All diagnostic messages printed during scanning MUST use `pb.println(...)` or `mp.suspend(|| println!(...))` to avoid leaving orphan progress bar lines in terminal history.
2. **Accurate Counter Tracking:**
   - Ensure `pb.inc(1)` or atomic counter updates occur as each task or channel message completes, so the bar reaches `N/N` (e.g., `31/31`).
   - Call `pb.finish_and_clear()` or `pb.finish_with_message(...)` upon scan completion before printing the final summary.
3. **Non-TTY / CI Fallback:**
   - If `!std::io::stdout().is_terminal()` or `--format json` is active, disable the interactive progress bar completely (`ProgressDrawTarget::hidden()`).

## Part B: HTML Report Template Refinements (`templates/report.html`)

Apply the following 5 UX/UI improvements to `templates/report.html` (and Rust report builders if needed):

### 1. Default Collapsed State
- Ensure Alpine.js component initialization defaults to `open: false` for all project cards when the page loads, so the report opens in a clean, compact view.

### 2. Clean Card Headers (Hide Filesystem Paths when Collapsed)
- Remove the long filesystem manifest path (e.g. `/Users/abstract/CODE/CES/babette/package.json`) from the collapsed card header row.
- Keep only: `[Ecosystem Badge] [Project Name] [Breaking/At-Risk/Safe Summary Badges]`.
- Place the full filesystem path inside the expanded card body header (e.g., as a subtitle next to manifest details).

### 3. Move 'Update All' Button Inside
- Remove the `[Update All]` button from the collapsed card header row.
- Position the `[Update All]` action button inside the expanded card body header area (e.g., next to table filter actions).

### 4. Prominent Expand/Collapse Chevron & Hover Affordance
- Add an explicit, visible SVG chevron icon (`<svg class="w-4 h-4 transition-transform duration-200" :class="{ 'rotate-90': open }">...`) on the far left of each project card header.
- Add hover states (`hover:bg-slate-800/60 cursor-pointer select-none`) to the entire card header to make it clearly interactive.

### 5. Smart Dependency Grouping & Sorting
- Sort dependencies within each project card by risk severity first, then alphabetically:
  1. 🔴 **Breaking** (Major SemVer jumps)
  2. 🟡 **At-Risk** (Minor/Patch with potential risk)
  3. 🟢 **Safe** (Clean minor/patch updates)
  4. ⚪ **Up to Date** (Already on latest version)
- Within each status group, sort packages alphabetically by name (`a.name.cmp(&b.name)`).
