# Prompt for OpenCode — Issue #19: CLI Scanning UX & Version Bump to v0.2.0

## Context & Objective
Implement GitHub Issue #19 ("Improvement: review CLI interface when scanning") and prepare release **v0.2.0**.
Currently, during large scans, `rustydeps` provides minimal output, making it appear frozen. We need interactive progress indicators, repository counts, and dependency statistics while preserving clean CLI output in non-interactive / CI modes.

---

## Instructions for OpenCode Agent

### 1. Version Bump
- Update `Cargo.toml` version to `0.2.0`.
- Update any version assertions or constants in tests, Dockerfile, or CLI commands.

### 2. Dependency Addition
- Add `indicatif` to `Cargo.toml` for thread-safe progress bars and spinners.

### 3. CLI Scanning UX Enhancements (`src/cli.rs`, `src/scanner.rs`, `src/main.rs`)
- **Interactive Spinner & Progress Bar:**
  - Display an animated spinner during folder discovery and registry fetching.
  - When total project/repository count is determined, show a progress bar counter: `[X/N]` repositories scanned.
- **Per-Project Dependency Metrics:**
  - Print a summary or status line for each analyzed repository (e.g., `✔ Scanned 'my-monorepo/backend': 18 dependencies (Cargo)`).
- **Non-TTY & CI/CD Graceful Fallback:**
  - Detect if stderr is a TTY (`indicatif` handles this automatically, or check `atty` / `is_terminal`).
  - Disable spinners/animations when running in CI or non-interactive environments, or when `--format json` is used.

### 4. Verification & Testing
- Run `cargo fmt --all --check`
- Run `cargo clippy --all-targets -- -D warnings`
- Run `cargo test`
- Run `cargo build --release`
- Verify CLI scanning manually: `cargo run --release -- scan .`

### 5. Wiki Update (OKF / Karpathy LLM-Wiki Compliant)
- Create or update the Wiki entry for CLI UX improvements under `doc/raw/YYYY-MM-DD/cli-scanning-ux.md`.
- Ensure strict OKF header metadata (`title`, `type: report`, `status: done`, `version: 0.2.0`, `tags`).
- Update `[[index]]` and `[[log]]` in the project wiki.

### 6. Git Branch & Draft Pull Request
- Create branch `feat/cli-scanning-ux` off `development`.
- Commit all changes with conventional commit messages (e.g., `feat(cli): add interactive progress bars for scanning (#19)`).
- Push branch and create a **Draft Pull Request** targeting `development`.
- Reference `Closes #19` in the PR description.
